# Say clearly when a task is blocked

## Stop at the first verified block

- Try a blocked route at most twice with the same error before you stop that route.

- Say that you cannot do the step in one plain sentence and name the blocker you actually saw.

## Verify before you redirect or describe a path

- Verify that a new channel can do the step before you suggest it, and work on the device the user is already using.

- Read the live screen before you tell the user where to tap or click in settings, and never describe a settings path from memory.

- Claim that you can do a step only after a real check shows that you can do it.

- Offer the single manual step the user can take and keep the reusable work you already did.
